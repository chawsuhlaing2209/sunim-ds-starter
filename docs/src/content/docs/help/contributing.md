## Design is human. Everything downstream of it is an agent

One job each, and the boundary matters more than the list.

| | Does | Never does |
|---|---|---|
| 🎨 **Human** | Designs, exports the tokens, marks a design done, approves | — |
| 🔨 **Engineer** | Builds and fixes | Verifies its own work |
| 🧪 **QA** | Tests and reports | Repairs |
| 🚀 **DevOps** | Ships what QA passed | Changes what was tested, on the way |
| 📝 **Doc generator** | Writes what a component is *for*, generates this site from it | Changes a component to make its documentation true |
| 📦 **Release** | Decides whether a shipped component can be lived with in public, prepares the package | Repairs anything, holds a publish credential, bumps a version |
| 📋 **PM** | Audits the registry and reports | Writes anything but a report |

**No agent approves its own work, and no agent bumps the version.** That number is
a promise to people outside this repository, and promises are made by whoever will
be held to them.

### They hand over through the registry, never in conversation

One agent writes evidence into a column it owns, a formula derives a status from
it, and the next agent picks up the rows carrying its status. An agent that writes
into a column it does not own has broken the handoff for everyone downstream.

This is why "the registry records evidence, never intention". A row does not say
what someone means to do; it says what has been produced, with a link to it.

## Which files are generated

The same rule as `build/tokens/`: editing a generated file lasts until the next
build, and the thing it disagreed with is still wrong.

| Generated by `scripts/generate-docs.mjs` | Yours to edit |
|---|---|
| `docs/…/index.mdx` — the home page | `docs/…/designing/*` |
| `docs/…/core/components/*` | `docs/…/developing/*` |
| `docs/…/core/tokens.md` | `docs/…/styling/*` |
| `docs/…/get-started/changelog.md` | `docs/…/skills/*` |
| `docs/…/get-started/versioning.md` | `docs/…/help/*` |
| `docs/src/styles/tokens.generated.css` | `docs/…/get-started/roadmap.md`, `news.md` |

The generated column is in `docs/.gitignore`, so a hand edit is not even
committed — it disappears at the next `npm run docs:build` and nobody reviews it.

**To change a generated page, change its source:**

| Page | Source |
|---|---|
| A component's *When to use* | `src/components/<Name>/<Name>.intent.json` |
| A component's props table | The doc comment above each prop in `<Name>.tsx` |
| A component's variant matrix | Its stories |
| The tokens page | `tokens/tokens.json`, then `npm run build:tokens` |
| The changelog | `CHANGELOG.md` — the same file that ships inside the package |
| The versioning page | `VERSIONING.md` |

## Why none of it is hand-written

A page written separately from the component drifts from it, and **the drift is
invisible**: a page describing a prop that was renamed last month still reads
perfectly. Generating it means the page is wrong only when the component is wrong.

The part that matters more is the refusal. The intent file is not written for this
site — it is written once, and two different things read it through one module,
`scripts/lib/contract.mjs`:

- **📦 Release's gate 6** fails a release if the intent is missing, thin,
  placeholdered, or naming a token the component does not actually use.
- **This site** turns the same file into the *When to use* section — and
  **refuses to publish a page for a component whose intent would fail that gate.**

So the site cannot document something the release gate would have rejected.
Without that, the two halves drift apart quietly and the failure mode is a
published page confidently describing a component that was never allowed to ship.

The registry gates it a second time: **a component is documented only once it
reads `Completed`.** A page for something that has not shipped reads exactly like a
page for something that has, and the first a reader learns of the difference is an
import that does not resolve. `--force` can forgive an incomplete intent. It can
never forgive a component that has not shipped.

## Running it locally

```bash
npm install
npm run build:tokens
npm run storybook          # :6006 — where components render
```

The reference site is a **separate npm package** and nothing in it may import from
`src/`. It documents the surface; it is not part of it.

```bash
npm run docs:install
npm run docs:dev           # :4321 — generates, then serves
```

`docs:dev` passes `--storybook http://localhost:6006` on purpose. The deployed
Storybook sends `frame-ancestors 'self'`, so every embedded frame on a page served
from `:4321` comes up blank — pointing them at a local Storybook, which sends no
CSP, is the difference between seeing your change and seeing nothing.
[Embedding](/help/embedding/) has the full picture, including the second header on
the other origin that has to agree.

| | |
|---|---|
| `npm run build` | The library: tokens, then Vite, then types, then CSS |
| `npm test` | Vitest |
| `npm run lint` | `tsc --noEmit` |
| `npm run docs:build` | Regenerate and build this site |
| `npm run security-check` | The gate every deploy passes, before and after |
| `npm run release-review` | The seven gates, per component |

## The failures worth naming

Every one of these has happened here.

- **Inventing a token that does not exist.** Report the gap and stop. A value
  nobody chose, in a file that is regenerated, is worse than a blocked build.
- **Copying a component's styles instead of importing the component.** The copy
  stops following the tokens the moment the palette moves.
- **Raw hex, px or font values inside a component file.** Every visual value
  references a semantic token. A component referencing `#2ba4ec` is wrong; it
  should reference `--color-accent-ink`.
- **A placeholder in a document a gate reads.** `color.bg.{intent}` reads well and
  checks nothing.
- **Editing a component so that its intent becomes true.** The gap is the finding.
- **Adding a dependency to solve a problem the stack already solves.** This
  repository *is* the component library.

## Before you open a pull request

- `npm run lint && npm test` pass.
- No hand-edited file from the generated column.
- If you changed a component, its intent still describes it — and `dont_use_when`
  still names an alternative for every case in it.
- If you changed the public surface, say so in the description. **Adding an export
  is a release decision**, not a housekeeping one.
- Nothing in the diff contains a token, a key, or a base or record ID. This
  repository is public and so is its history.
